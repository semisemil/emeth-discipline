HANDOFF: Codex Desktop Graph Panel
0. 현재 상태
- 대상: Windows용 Codex 데스크톱 앱만 해당. Codex CLI, VS Code 확장, ChatGPT 앱은 범위 밖이다.
- 이미 완료: Codex 앱에 대한 CDP 연결 및 코드 실행 검증 성공. 해당 검증은 되풀이하지 말고, 이미 성공한 연결 방식과 작업물을 재사용한다.
- 아직 미확인: Codex 오른쪽 영역에 실제 패널을 안정적으로 추가하는 일, 그래프 렌더링 및 데이터 갱신.
- 출발점: 기존 CDP 검증 코드/실행 방식부터 확인한다. 성공한 연결 방식이 무엇이었는지 임의로 가정하지 않는다.
1. 목표
Codex 데스크톱 앱 안에, 대화와 동시에 볼 수 있는 Graph 패널을 추가한다. 위치는 사용자가 제시한 화면의 오른쪽 Proofline 변경사항 영역이 우선 후보이며, 기존 오른쪽 패널의 탭으로 추가하거나 해당 패널과 자연스럽게 전환할 수 있는 형태를 선호한다.

그래프는 ARTEX처럼 깔끔한 노드·연결선 기반의 조작형 도식도여야 한다. 확대·이동, 노드 선택, 상세 정보 확인, 접기/펼치기, 화면 크기에 따른 재배치가 가능해야 한다. Mermaid는 사용하지 않는다.
그래프의 3가지 용도
1. Architecture Memory 시각화: 모듈·계층·의존 관계·설계 결정·근거를 보여준다.
2. 에이전트의 탐색/판단 기록 시각화: 명시적으로 기록한 목표·가설·확인 사항·도구 실행 결과·선택·결론의 연결을 보여준다. 모델의 비공개 내부 추론 내용을 추출하거나 복원하려는 기능은 아니다.
3. 사용자 설명용 시각화: 개념 비교, 동작 흐름, 원인과 결과, 구성 요소 관계 등을 이해하기 좋은 그래프로 만든다.
2. 반드시 지킬 조건
- MCP 사용하지 않음.
- 외부 오버레이 사용하지 않음. 그래프는 Codex 앱의 실제 화면 구성 안에 삽입한다.
- 대화 메시지 내부에 출력하지 않음. 전용 오른쪽 사이드 패널에 표시한다.
- 별도 브라우저/내장 브라우저 탭에서 열지 않음.
- 공식 Codex의 설치 파일(app.asar 등) 직접 수정·교체·재서명은 1차 구현에서 제외한다. 이미 성공한 CDP 기반 런타임 UI 삽입을 우선 활용한다.
- Graph를 표시하려고 기존 Proofline 변경사항 기능을 가리거나 제거하지 않는다.
- 사용자에게 별도 상주 EXE 설치·실행을 요구하지 않는 방향을 우선한다. 다만 CDP 주입/재연결에 실제로 필요한 실행 과정은 숨기지 말고 명확히 문서화한다.
- Codex 앱 업데이트나 화면 구조 변경으로 깨질 수 있으므로, 실패 시 Codex 기본 화면을 정상 유지하도록 만든다.
- UI와 그래프 데이터는 특정 Emeth 스킬에 종속시키지 않는다.
3. 권장 구성과 책임 분리
A. Codex UI Adapter
- 기존 검증에 성공한 CDP 연결을 재사용해 Codex의 렌더러(화면)에 최소한의 코드/CSS를 삽입한다.
- 우측 기존 패널 영역을 찾아 Graph 탭 또는 전용 패널을 등록한다.
- 기존 Proofline 탭/내용/버튼을 보존하고, 대화 영역과 겹치지 않도록 실제 레이아웃 공간을 사용한다.
- 화면 전환·프로젝트/스레드 변경·크기 변경·테마 변경·앱 재시작 시 안전하게 다시 붙는다.
- 여러 번 삽입되어도 중복 탭·이벤트 처리기가 쌓이지 않게 한다. 해제/정리 함수 제공.
- Codex의 내부 요소 이름은 바뀔 수 있다. 화면 요소를 찾는 코드와 Graph 자체를 분리하고, 찾기에 실패하면 패널 삽입만 건너뛴다.
B. Graph Renderer
- React Flow 기반을 우선 검토한다. Codex 자체 React 트리와 충돌하지 않도록 독립된 마운트 지점을 사용한다.
- 노드 종류별 색/아이콘, 엣지 스타일, 자동 배치, 확대/축소, 전체 보기, 선택 시 상세 정보, 검색/필터를 단계적으로 구현한다.
- 표시할 정보가 없으면 빈 상태를 보여준다. 많은 노드가 있을 때 성능이 급격히 떨어지지 않도록 한다.
- CSS가 Codex 본래 화면에 번지지 않도록 스타일 격리 및 충돌 방지에 신경 쓴다.
- 외부 CDN에 의존하지 않고 배포 시 필요한 JS/CSS를 함께 묶는다.
C. 공통 Graph 데이터 형식
- 그래프 생성자와 UI를 분리한다. 생성자는 JSON 데이터를 만들고, UI는 표시만 담당한다.
- 최소 항목: 스키마 버전, 그래프 ID, 용도(architecture/exploration/explanation), 제목, 노드(id, type, label, 상세 설명, 상태, 출처), 연결(id, source, target, 관계 종류).
- 노드 ID는 갱신 시에도 유지한다. 전체 데이터 재전송뿐 아니라 변경분 반영이 가능하도록 확장할 수 있게 설계한다.
- 데이터는 검증·크기 제한·문자열 안전 처리를 거친다. 그래프 텍스트를 HTML/실행 코드로 취급하지 않는다.
- Graph는 원본 기록을 대체하지 않는다. Architecture Memory의 원본은 기존 저장소에 그대로 남는다.
예시:
{
  "schemaVersion": 1,
  "graphId": "architecture-main",
  "kind": "architecture",
  "title": "시스템 구조",
  "nodes": [
    { "id": "ui", "type": "module", "label": "UI" },
    { "id": "service", "type": "module", "label": "Service" }
  ],
  "edges": [
    { "id": "ui-service", "source": "ui", "target": "service", "type": "depends_on" }
  ]
}
D. 데이터 전달 및 스킬
- 1차: 샘플 JSON을 CDP로 주입된 Graph Renderer에 전달해 정상 표시되는지 확인한다. 이미 작동한 CDP 제어 코드를 그대로 활용할 것.
- 2차: 로컬 JSON 파일/스킬 출력과 화면을 연결한다. 파일 변경을 앱 안에 전달하는 방법은 기존 CDP 동작 환경에 맞춰 선택한다. 외부 상주 서버나 MCP를 당연한 전제로 두지 않는다.
- 3차: 범용 Graph Skill이 사용자의 요청에 따라 그래프를 생성하도록 한다. Architecture Memory 연결은 선택적 어댑터로 추가한다.
- 추후: 사용자가 그래프 노드에 남긴 피드백을 Codex에 전달하는 양방향 연결. 1차 필수 범위가 아니며, 피드백만으로 원본 메모리나 코드를 자동 수정하지 않는다.
4. 구현 순서
단계 1: 오른쪽 패널 삽입 검증 (최우선)
- 이미 성공한 CDP 환경에서 Codex의 우측 Proofline 변경사항 영역 구조를 확인한다.
- Graph 탭/패널을 최소한의 더미 내용으로 실제 앱 레이아웃에 삽입한다.
- Proofline ↔ Graph 전환, 창 크기 변경, 스레드 변경, 패널 닫기/재열기 테스트.
- 성공 조건: 오버레이가 아닌 실제 오른쪽 UI 영역에 표시되고 기존 기능을 손상시키지 않는다.
- 실패 시: Codex 파일을 바로 수정하지 말고 원인을 기록한다. 가능한 다른 앱 내부 영역/삽입 지점을 평가한 뒤 선택한다.
단계 2: 그래프 UI
- 독립 Renderer를 만들고 간단한 노드/연결 예제로 시작한다.
- 자동 배치, 확대/이동, 노드 상세 보기, 다크·라이트 모드 및 패널 크기 대응.
- 앱의 기존 조작(스크롤, 단축키, 입력창 포커스)을 방해하지 않는지 확인한다.
단계 3: 데이터 연결
- JSON 스키마 및 검증 구현.
- 정적 샘플 → 외부 JSON 입력 → 갱신 반영 순으로 확장.
- 데이터가 변경되어도 사용자의 현재 확대 배율·위치를 불필요하게 초기화하지 않는다.
단계 4: 범용 사용 사례
- 먼저 explanation과 exploration 샘플을 만든다.
- 그다음 기존 Architecture Memory의 실제 데이터 형식을 확인해 architecture 변환기를 만든다. 원본 구조를 임의로 바꾸지 않는다.
- AI의 탐색 기록은 사용자에게 공개하도록 명시적으로 작성된 단계·관찰·근거·결론으로 제한한다.
단계 5: 피드백 및 편의 기능 (후속)
- 노드에 댓글 또는 수정 제안을 남기는 인터페이스.
- 해당 노드/출처가 포함된 피드백을 Codex에 전달하는 기능.
- 그래프별 저장·불러오기, 선택한 프로젝트/스레드와 연결, 필요한 경우 실시간 갱신.
5. 완료 기준
- [ ] Windows Codex 데스크톱 앱 오른쪽에서 Graph 패널을 열고 닫을 수 있다.
- [ ] 기존 Proofline 변경사항 영역의 기능을 정상적으로 사용할 수 있다.
- [ ] 그래프가 기존 화면 위에 겹치는 독립 창이 아닌 앱 내부 요소다.
- [ ] 노드 확대/이동/선택 및 상세 정보 보기가 동작한다.
- [ ] JSON을 바꾸면 표시되는 그래프가 갱신된다.
- [ ] 프로젝트/스레드 전환, 창 크기 변경, 테마 변경, 재시작 후에도 화면이 정상이다.
- [ ] UI 삽입 실패 시 Codex 기본 기능이 유지된다.
- [ ] MCP, 외부 오버레이, 브라우저 탭, Codex 설치 파일 수정 없이 동작한다.
- [ ] Architecture Memory 연동 없이도 설명용 그래프를 독립 실행할 수 있다.
6. 개발 시 주의할 점
- CDP 성공 여부는 기완료 사실이다. 다시 CDP 연결 방법 탐색에 시간을 쓰지 않는다.
- CDP 성공 ≠ 원하는 위치에 패널 추가 성공이다. 패널 삽입 검증을 최우선으로 한다.
- CDP 디버깅 포트는 가급적 로컬(127.0.0.1)로 제한한다. 외부에서 접근 가능한 상태로 두지 않는다.
- 내부 DOM/CSS/React 구현에 의존하는 부분은 앱 업데이트에 취약하다. 버전 확인, 실패 감지, 해제 및 복구 경로를 준비한다.
- 패널을 추가하기 위해 내부 React 트리를 무리하게 변경하거나 기존 컴포넌트를 삭제하지 않는다.
- Renderer와 데이터 형식은 다른 앱에서도 재활용 가능한 독립 코드로 유지한다.
- Graph를 무조건 자동 생성하지 않는다. 우선은 사용자 요청 시 생성·갱신하는 방식으로 시작한다.
7. 개발 담당자에게 요청하는 첫 작업
전체 기능을 한꺼번에 만들지 말 것. 우선 현재 CDP 검증 코드를 확인하고 Windows Codex 데스크톱 앱의 오른쪽 Proofline 변경사항 영역에 정식 레이아웃을 차지하는 Graph 탭/패널을 추가하는 최소 구현부터 완성한다.

첫 작업 결과에는 다음을 반드시 포함한다.
1. 실제로 삽입된 화면 캡처 및 동작 확인 결과.
2. 수정한 파일과 패널 삽입 지점에 대한 간단한 설명.
3. Codex 재시작·화면 전환·업데이트 시 예상되는 문제.
4. 실패 시 기본 화면을 복구하는 방법.
5. 이후 React Flow를 연결할 수 있는 독립 마운트 지점.
이 첫 단계가 성공한 뒤에만 전체 Graph Renderer와 스킬 연동을 진행한다.
